> 달라진 둘은 날짜가 붙어 있으며 달라진 이유도 저장소 안에 적혀 있다.

## 그래서 남긴 것 ― 0을 0으로 지킨다

빈 캡처를 **0으로 만들어 놓았는데, 0인지 보는 검사가 없었다.**

기존 `test_doc_storage_atomicity.py` §4는 두 가지를 지킨다.

- 판별 함수 `status_overlay_has_data()`가 빈 골격을 걸러 내는가 (합성 HTML)
- `collect_status()`가 **저장 직전에** 그 관문을 두는가 (소스 검사)

빠진 것은 **실제 디스크**다. 그리고 관문은 `collect_status()` **하나에만** 있다 ―
다른 경로로 파일이 들어오면(운영 스크립트, 수동 복사, `collect_documents.py`)
관문을 지나지 않는다. 한 번 저장되면 `doc_exists()`가 완료로 판정해
**영구히 재수집에서 빠진다**(BUGS #22/#50과 같은 부류).

`test_document_status_sync.py` §13 을 신설했다. 이 파일 §11이 같은 자리에서 이미 세운
원칙을 그대로 적용한다 ― *"지금 0이므로, 1건이라도 생기는 순간이 곧 회귀다."*

```
[PASS] 검사할 status.html이 존재한다(검사가 공허하지 않다)
    status.html 163건
[PASS] 빈 캡처가 디스크에 없다: 0
[PASS] 읽을 수 없는 status.html이 없다: 0
```

판정은 **운영 함수 `status_overlay_has_data()` 에 묻는다.** 기준을 검사에 베껴 적으면
두 기준이 갈라져도 통과한다 ― 그것이 막으려는 결함 자체다.

> `check_true("검사할 status.html이 존재한다(검사가 공허하지 않다)", ...)` 는
> §11이 경고한 **빈 집합 함정** 방지다. 파일이 0건이면 "빈 캡처 없음"이 공허하게 참이 된다.
