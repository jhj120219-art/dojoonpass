## 0. 어떻게 발견했나

Sprint 225 문서를 쓰다가 내가 만든 문서에 백스페이스 바이트(0x08)가 들어갔다.
원인을 확인하려고 **저장소 전체를 훑었더니 내 것이 아닌 것이 하나 더 있었다.**

```
tests/source-contract.test.mjs   \b x2      <- 작업트리 변경 없음 = 원래 그랬다
```

`git diff` 가 비어 있으므로 커밋된 상태 그대로다(마지막 수정 `21430db`).

## 1. 결함 — 절대 실패할 수 없는 단언

```js
assert.ok(
  !/<0x08>formatPrice<0x08>/.test(src),
  '마이페이지가 축약 표기(formatPrice)를 씁니다 — 청구 금액이 실제와 어긋납니다'
)
```

`/\bformatPrice\b/`(단어 경계) 로 쓰려던 것이 파일에 **백스페이스 문자 자체**로
들어가 있었다. 정규식은 이제 *"백스페이스 + formatPrice + 백스페이스"* 를 찾는다 —
소스에 그런 것이 있을 리 없으므로 **항상 일치하지 않고**, `!` 가 붙어 있으니
단언은 **항상 참**이다.

이 가드가 지키려던 것은 실제 금액 결함이다.

> `formatPrice` 는 12,900원을 "1만"으로 만든다(-22%). 구독 카드는
> `toLocaleString() + '원'` 으로 정확히 쓰는데 내역만 축약하면
> **같은 결제가 화면마다 다른 금액으로 보인다.**

### 겉보기로는 알 수 없다

에디터는 그 바이트를 거의 보여 주지 않는다. 문법 오류도 아니고, 테스트는 **초록불**이다.
`node --test` 는 23/23 통과라고 말한다. 지금 코드가 실제로 `formatWon` 을 쓰고 있어서
**결과까지 맞다** — 틀린 것은 "그것이 검증되고 있다"는 믿음뿐이다.

### 변이로 확인 — 옛 가드는 정말로 놓쳤다

`src/app/mypage/page.tsx` 의 `formatWon(` 을 `formatPrice(` 로 바꿔(=결함 주입)
두 판본을 각각 돌렸다.

```
수정 후 가드        [검출]   테스트 실패
수정 전 가드(재현)   [놓침]   테스트 **통과**
```

*"가드가 존재함"과 "가드가 동작함"은 다른 사실이다.* 이 저장소가 반복해 적어 온 원칙이
여기서 그대로 확인됐다.

## 2. 해결

```js
!new RegExp(String.raw`\bformatPrice\b`).test(src),
```

정규식 리터럴 대신 `String.raw` + `RegExp` 로 쓴다. 같은 사고가 다시 나면
이번에는 **패턴 문자열이 눈에 보이게 깨진다.**

그리고 같은 자리에서 **그 검사가 공허하지 않음을 증명**하게 했다.

```js
const probe = new RegExp(String.raw`\bformatPrice\b`)
assert.ok(probe.test(`const x = formatPrice(1)`),  '검사기가 formatPrice 를 못 잡는다')
assert.ok(!probe.test(`const x = formatPriceLike(1)`), '단어 경계가 동작하지 않는다')
```

합성 입력으로 **잡아야 할 것 / 잡으면 안 될 것**을 둘 다 시험한다.
검출기가 죽으면 조용히 통과하는 대신 여기서 먼저 운다.

---

## 3. 같은 계열 전수 탐색 + 재발 방지

하나를 고쳤으니 같은 계열을 전부 찾았다. 이런 사고는 `\b` 만이 아니라
`\0`(0x00) `\a`(0x07) `\v`(0x0B) `\f`(0x0C) `\e`(0x1B) 에서도 난다.

```
훑은 파일 390개 (.py .mjs .js .ts .tsx .md .json .css)
발견                                              1곳 (위 그것뿐)
```

`test_console_encoding.py` 에 상시 검사를 신설했다. 이 파일이 이미 소스를 바이트로
훑고 있고 제외 규칙(`SKIP_DIRS`)을 공유하기 때문에 형제 검사로 두는 것이 맞다.

```
훑는 대상   .py .mjs .js .ts .tsx  (저장소 사본/의존성 제외)  실측 242개
고정        제어문자로 굳은 이스케이프 **0개**
하한        훑은 파일 >= 80  (열거가 깨져 0개를 훑고 통과하는 것 방지)
자체 검증   진짜 바이트는 잡고, 정상 두 글자 표기(역슬래시+b)는 잡지 않는다
```

### 변이 3/3 검출

```
.py  파일에 제어문자를 넣는다           -> FAIL

```

## 4. 왜 이 사고가 나는가 (다음 사람을 위해)

파일을 **도구를 거쳐** 쓸 때 역슬래시가 한 겹 사라지면 `"\\b"` 가 `"\b"` 로 해석되고,
그것이 파일에는 0x08 바이트로 떨어진다. 이번에도 같은 일이 실시간으로 일어났다 —
Sprint 225 문서를 heredoc 으로 넘기면서 `\b` 가 그대로 굳었고, 그것을 고치려던
스크립트마저 같은 경로에서 또 깨졌다.

**대처**: 역슬래시가 들어가는 내용은 heredoc 으로 넘기지 말고 **파일로 써서 실행**한다.
그리고 쓴 뒤에는 위 검사로 확인한다.
