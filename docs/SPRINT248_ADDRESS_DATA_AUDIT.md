## 4. ★ 결함 — 중첩 대괄호 4건이 면적을 통째로 잃고 있었다 (수정 완료)

### 원인

```js
fullAddress.match(/\[([^\]]*)\]\s*$/)     // 예전
```

`[^\]]*` 는 안쪽 `]` 를 넘지 못한다. 그래서 대괄호가 **중첩된** 주소에서 매치 자체가
실패하고 `null` 이 되어 화면에 아무것도 안 나온다. 넷 다 면적이 멀쩡히 적혀 있다:

```
id=258   [토지 전[현황:묵전(죽림)] 105㎡ ...]                 -> 105㎡
id=259   [토지 전[(현황:전 및 묵전(임야)] 694㎡ ...]           -> 694㎡
id=1610  [토지 임야 6571㎡ ... [... 5178분의 521 제외]]       -> 6571㎡
id=6273  [건물 ... 97.58㎡ ... 46.4㎡ [현황: 멸실]]           -> 143.98㎡
```

### 고침 — 고치기 전에 전수로 대조했다

탐욕적 `(.*)` 로 바꾸면 **바깥 대괄호 전체**를 잡는다. 소스를 건드리기 전에 두 정규식을
1,876행 전부에 돌려 비교했다:

```
동일          1,872
새로 파싱됨        4      <- 위 네 건
값이 달라짐        0
파싱을 잃음        0      (회귀 없음)
```

### 겸사겸사 — 테스트가 붙을 수 있는 자리로 옮겼다

`parseArea` 는 `.tsx`(JSX) 안에 있어서 Node 의 타입 스트리핑으로 import 할 수 없었다.
즉 **검색 결과 카드마다 찍히는 값인데 동작이 한 번도 검증된 적이 없었다.**
`src/lib/format.ts`(파일 첫 주석이 "공용 표시 포맷 함수"라고 선언한 자리, `ResultList`
가 이미 import 하던 곳)로 옮겼다. 동작은 위 정규식 한 곳 말고는 그대로다.

### 회귀 + mutation

## 5. ★ 결함 — `datetime('now')` 에 localtime 이 빠져 있었다 (수정 완료)

`test_pipeline_integrity.py` 의 두 실패 중 하나가 이것이었다. 지난 보고에서 이 파일의
실패를 통째로 "크롤 정지"로 묶었는데, **하나는 별개의 진짜 결함**이었다.

```
test_image_queue_transition.py:371   last_attempt_at=datetime('now','-2 day')
```

SQLite 의 `'now'` 는 **UTC** 다. 한국(UTC+9)에서 UTC 로 "2일 전"을 만들면 제품이
로컬 시각으로 판정하는 값과 9시간 어긋나, 경계 근처에서 재시도 판정이 흔들린다.
저장소는 이 형태를 **금지**하고 있고(`test_sqlite_now_is_localtime()`), 그 가드가
정확히 잡아 준 것이다. `datetime('now','localtime','-2 day')` 로 고쳤다.

```

## 7-B. ★ 결함 — 루트 스크립트 2개가 **확인 없이** 운영 DB 를 고쳤다 (수정 완료)

주소 감사 뒤 dead code / 실행경로 감사를 이어가다 나왔다.

이 저장소의 데이터 수정 도구는 관례가 확실하다 — `backfill_*.py` / `repair_*.py` /
`reset_failures.py` / `unlock_retry.py` 는 **기본 dry-run 이고 `--apply` 를 줘야 쓴다**
(`reset_failures.py` 는 dry-run 에서 `sys.exit(0)` 하는 것까지 확인했다).
**두 파일만 예외였다:**

```
fix_validator.py    python fix_validator.py   -> 곧바로 UPDATE auction SET ... + commit
add_test_queue.py   python add_test_queue.py  -> 곧바로 document_queue 에 INSERT
```

둘 다 과거 디버깅 세션의 일회성 스크립트가 그대로 커밋된 것이다. 이름만 보고
"확인용이겠지" 하고 실행하면 운영 데이터가 바뀌고, 되돌릴 방법이 없다.

`add_test_queue.py` 는 **SQL 문자열이 없어서** 처음 스캔에 안 걸렸다 —
`enqueue_documents(...)` 함수 호출로 쓴다. SQL 텍스트만 찾던 내 도구의 한계였고,
그래서 아래 가드는 **함수 호출 형태도** 본다.

### 고침 — 관례에 맞추고, 동작은 그대로 두었다

둘 다 `--apply` 없이는 아무것도 쓰지 않게 바꿨다. `--apply` 를 주면 예전과 같다.
`sys.path` 도 `os.getcwd()` -> `__file__` 기준으로 바꿨다(Sprint 246 과 같은 계열).

운영 DB 를 앞뒤로 재서 dry-run 이 정말 무해한지 확인했다:

다른 cwd 에서도 rc=0, 찌꺼기 파일 없음
```

### 가드 + mutation

**저장소 루트의** 추적 `.py` 33개만 본다 — `api/v1/*.py` 같은 패키지 모듈은 쓰기가
