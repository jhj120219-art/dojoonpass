## 1. 무엇이 문제였나

Sprint 145가 `sanitize_path_segment()`로 경로 조각 정규화를 한 곳에 모았는데,
사본이 6곳 남아 있었다. 정본과 두 가지가 달랐다.

| | 정본 | 남아 있던 사본 |
|---|---|---|
| `/` 치환 | O | O |
| `\` 치환 | **O** | **X** |
| `""` / `.` / `..` -> `_` | **O** | **X** |

Windows에서는 `\` 도 경로 구분자다. `2024타경1\2` 가 오면 크롤러는 `2024타경1_2` 에 쓰고
백필은 `2024타경1\2`(= 디렉터리 두 단계)를 계산해 **같은 문서를 두 경로로 본다.**
BUGS #50/#64/#111 계열이다.

### 아이러니

`backfill_doc_raw.py` 자신의 docstring이 이렇게 적고 있었다.

> 경로 규칙을 여기서 새로 쓰지 않고 `crawler/doc_paths.py`의 파일명 표를 그대로 쓴다
> — 규칙이 두 벌이 되면 백필이 뷰어와 다른 파일을 가리키게 된다.

파일명 표는 실제로 import 했다. 그런데 **정규화 규칙은 바로 아래 줄에서 다시 썼다.**

## 2. 고치기 전에 "기존 경로가 바뀌지 않는다"를 증명했다

이 파일은 `doc_raw.storage_path` 를 만든다. 규칙을 바꿔 경로가 달라지면
**멀쩡한 문서가 유실로 보인다.** 그래서 먼저 실데이터로 대조했다.

```
검사한 (case_no, item_no) 조합 7,504개
   auction_item                1,876
   document_status 조인          5,628

옛 규칙과 새 규칙이 다른 경로를 만드는 경우 :  0건
   (역슬래시 포함 행 0 · '.'/'..'/빈값 0 · 슬래시 포함 425행은 양쪽 동일 결과)
```

**기존 경로는 하나도 바뀌지 않는다.** 그 위에서 수정했다.

## 3. 수정 후 — 정본과 완전히 같은 경로를 만든다

`backfill_doc_raw.py` 의 결과를 정본 `_doc_dir_path()` 와 직접 대조했다.

```
case='2024타경117502' item='1'    -> 일치
case='2024타경1/2'    item='2'    -> 일치
case='2024타경1\2'    item='1'    -> 일치      <- 수정 전에는 갈렸다
case='..'            item='1'    -> 일치      <- 〃
case='2024타경1'      item=None   -> 일치
case=''              item=''     -> 일치
6/6 일치
```

역슬래시 처리 차이도 그대로 확인된다.

```
입력             '2024타경1\2'
옛 규칙(/ 만)     '2024타경1\2'     <- 경로 구분자로 남는다
정본 sanitize    '2024타경1_2'
```

## 4. ★ 검사를 목록에서 전수 스캔으로 바꿨다

이게 이번 스프린트의 핵심이다. 이 결함은 **목록 기반 검사가 두 번 연속 놓친** 것이다.

```
Sprint 145   sanitize_path_segment() 로 규칙을 한 곳에 모았다
Sprint 153   repair_document_status.py 가 목록에 없어 사본이 살아남았다  -> 목록에 추가
Sprint 160   backfill_doc_raw.py 가 목록에 없어 또 살아남았다 (4곳)
```

**목록을 한 줄 더 늘리는 것은 세 번째를 예약하는 일이다.** `test_doc_path_safety.py` §7을
저장소 전체 `.py` 스캔으로 교체했다(실측 146개 파일).

제외는 두 가지뿐이고 둘 다 이유가 분명하다.

* `sanitize_path_segment()` 자신의 구현 한 줄 = 정당한 유일한 사본
* 주석 = 코드가 아니다 (사고 이력 인용을 위반으로 잡으면 "왜 고쳤는지 남기는 일"과 검사가 싸운다)

> **포함 목록과 제외 목록은 다르다.** 포함 목록은 새 파일을 **조용히 무시**한다(fail-open).
> 제외 목록은 새 파일을 기본으로 검사한다(fail-safe). 그래서 전자를 버리고 후자만 남겼다.

### Mutation — 3/3 잡힌다

```
M1 backfill 에 옛 사본 복원        exit=1 잡힘   ['backfill_doc_raw.py:81', ...]
M2 ★ 새 파일에 사본이 생긴 경우     exit=1 잡힘   ['__mut_newfile.py:3']
M3 정본 자신의 역슬래시 치환 제거    exit=1 잡힘   [FAIL] 역슬래시도 밑줄로: 'a\b' (expected 'a_b')
전 파일 원본 복원 확인 OK
```

**M2가 이번 변경의 값어치다** — 옛 목록 기반 검사로는 절대 못 잡던 경우다.
