## 1. 인가 전수 ― 41개 라우트를 익명으로 두드렸다

라우트를 손으로 고르지 않고 앱이 들고 있는 것을 그대로 썼다.

```
41개 라우트
  32개  익명 거부      (admin 16개는 403 / 사용자 16개는 401)
   8개  공개           / , /stats, /document-stats, /search, /search/regions,
                        /item/{id}, /item/{id}/documents/{type}, /plans
   1개  서명 보호       POST /payments/webhook/{provider}
```

공개 8개 중 정당성이 자명하지 않은 둘을 따로 봤다.

- **`/item/{id}/documents/{doc_type}`** ― 매각물건명세서/현황조사서/감정평가서다.
  유료 대상은 **등기부**이고 그것은 `/registry-requests/{id}/download`(401 확인)로만 나간다.
  문서 3종에 구독 게이트가 필요하다는 서술은 `docs/` 어디에도 없다. **제품 정책이므로 판단하지 않는다.**
- **`/payments/webhook/{provider}`** ― 인증이 없는 것이 정상이다(PG가 부른다).
  대신 HMAC-SHA256 서명을 **파싱보다도, DB 쓰기보다도 먼저** 검증하고,
  시크릿이 없으면 통과시키지 않으며(fail closed), `hmac.compare_digest` 로 비교한다.
  미검증 요청은 행을 남기지 않는다(Sprint 53의 저장소 증폭 차단). **적절하다.**

`test_api_regression.py` §33 이 이미 이 전수를 하고 있었고,
그 `PUBLIC_ENDPOINTS` 8개는 **내가 독립적으로 측정한 8개와 정확히 일치**했다.
분류 집계도 `public 8 / user 16 / admin 16 / signature 1 = 41` 로 맞는다.

## 2. ★ 그런데 그 검사는 조용히 좁아질 수 있었다

§33 은 `app.openapi()` 로 라우트를 열거한다. 문제는 이것이다 ―

> `include_in_schema=False` 인 라우트는 **스펙에 아예 나오지 않는다.**

즉 누가 보호 엔드포인트에 그 인자를 붙이면, §33 은 **실패하지 않고 그 엔드포인트를 안 본다.**
검사가 줄어드는데 초록불이라 줄어든 사실을 알 방법이 없다.

하필 그 인자를 붙이는 동기가 대개 **"내부용이라 문서에 안 띄우고 싶다"** 이다.
가장 민감한 것부터 검사 밖으로 빠지는 방향이다.

### 재현 ― 관리자 엔드포인트 하나를 스펙에서 숨겼다

```
M69  @router.get("/admin/users", include_in_schema=False)   (인가는 그대로 둠)

     분류: admin 16 -> 15          <- 검사 대상이 하나 줄었다
     기존 §33 검사 3종             -> 전부 PASS (초록불)
```

**기존 검사는 아무 말도 하지 않았다.** 이것이 이 스프린트의 실제 발견이다.

## 3. 고친 것 ― 스펙 밖 라우트를 고정

§33 에 검사 3개를 더했다. 스펙이 아니라 **앱의 라우트 구조**를 직접 세서 대조한다.

```
스펙에 없어 전수에서 빠지는 라우트 없음      (허용 목록 밖이면 실패)
허용한 스펙 밖 라우트가 실재한다            (죽은 예외가 남아 헐거워지는 것 방지)
HEAD 와 GET 의 인가 결과가 같다             (HEAD 가 우회로가 되지 않게)
```

2026-08-14 실측: 구조상 **42개** / 스펙 **41개**. 차이는 **문서 뷰어용 HEAD 하나**뿐이고,
그것은 공개 경로이며 GET 과 인가 결과가 같다(둘 다 404). 그 상태를 허용 목록으로 고정했다.

### 함정 하나 ― `app.routes` 를 그냥 훑으면 안 된다

이 FastAPI 버전은 `include_router` 결과를 `app.routes` 에 **평탄화하지 않고**
`_IncludedRouter` 로 감싼다. 그냥 훑으면 라우트가 **2개**만 보인다.

처음 만든 감사 도구가 정확히 그랬고, 출력은 이랬다.

```
등록된 라우트: 2개
A. 인증 없이 거부됨 ― 0개
B. 인증 없이 통과함 ― 2개
```

**"인가가 하나도 없다"가 아니라 "전부 공개인데 문제없다"로 읽힐 뻔했다.**
숫자가 41이 아니라 2인 것을 이상하게 여기지 않았다면 거짓 정상 판정이 그대로 남았다.
그래서 검사 코드는 감싼 것을 풀어서 세고, 그 사실을 주석에 남겼다.
