## 0. 무엇을 만들고, 무엇을 만들지 않았는가

`docs/SPRINT219B_MYLIST_EXPORT_FEASIBILITY.md` 가 실측으로 "**안전**"이라고 분류한
두 가지만 만들었다.

```
만든다        4-1 형식 중립 CSV 내려받기
              4-2 탭 구분 클립보드 복사
만들지 않는다  4-3 상대 서비스(지지옥션·탱크옥션 등) 전용 포맷  <- 형식 미확인
```

상대 서비스의 실제 입력 형식은 **여전히 확인하지 못했다**(사람의 확인이 필요하다).
추측해서 내보내면 *"붙여넣었는데 안 들어간다"* 가 되고, 그 실패는 우리 쪽에서 보이지 않는다.

## 1. 데이터를 왜곡하지 않는다

Sprint 219B 가 짚은 세 가지를 그대로 지켰다.

### 병합 사건을 쪼개지 않는다

실측: `auction_item` 1,876행 중 **425행(22.7%)** 의 `case_no` 가
`2008타경25092 / 2015타경19958` 형태다. 어느 쪽이 대표인지는 **법원 원천이 정하지 않았다.**
우리가 정하면 안 되므로 원본 문자열을 그대로 내보내고 판단은 사람에게 남긴다.

### 값을 축약하지 않는다

화면은 `formatPrice()` 로 "3.8억"처럼 줄여 보여 주지만 내보내기는 **숫자 원본**을 낸다.
축약은 12,900원을 "1만"으로 만들어(-22%) 계산에 못 쓰게 한다
(`tests/source-contract.test.mjs` 가 마이페이지 금액을 지키는 것과 같은 이유 —
그 가드가 실제로는 죽어 있었다는 것이 Sprint 226 의 발견이다).

### 없는 값을 대체값으로 감추지 않는다

```
값이 없다   -> 빈 칸        ('-' 나 0 을 넣지 않는다)
유찰 0회    -> "0"          (`!v` 로 판정하면 0 이 빈 칸이 되어 "없음"이 "모름"이 된다)
```

## 2. 열이 밀리지 않게 만드는 구조

헤더와 값 추출기를 **한 곳에 묶었다**. 둘을 따로 적으면 열이 밀려도 아무도 모른다.

```ts
export const COLUMNS = [
  { header: '법원',     get: (r) => str(r.court_name) },
  { header: '사건번호', get: (r) => str(r.case_no) },   // 병합 사건 원본 그대로
  ...
]
```

CSV 이스케이프는 RFC 4180 대로다. **실제로 걸리는 경우가 있다** —
물건종류 `상가,오피스텔,근린시설` 에 쉼표가 들어 있고, 감싸지 않으면 열이 2칸 밀린다.

## 3. 엑셀 BOM — 근거를 실측으로 남긴다

CSV 앞에 **UTF-8 BOM** 을 붙인다. 붙이지 않으면 한국어 Windows 엑셀이 cp949 로 읽어
소재지·법원명이 전부 깨진다.

실제로 내보낸 파일을 cp949 로 읽어 확인했다.

```
cp949 로 읽기 -> UnicodeDecodeError: 'cp949' codec can't decode byte 0xec in position 6
utf-8-sig 로 읽기 -> 정상
선행 바이트 -> 0xEF 0xBB 0xBF
```

이 저장소가 "BOM 파일을 utf-8 로 읽고 조용히 넘어가지 말라"고 적어 둔 것의 **쓰는 쪽**이다.

## 4. 회귀 — 이 저장소에서 처음으로 TypeScript 를 **실행**해 검증한다

지금까지 프런트 검사는 **소스 문자열 대조**와 **HTTP 블랙박스** 둘뿐이었다.
그 둘로는 "쉼표가 든 주소를 제대로 감쌌는가"를 볼 수 없다.

Node 24 는 TypeScript 를 **기본으로 타입 스트리핑**해 실행한다
(`process.features.typescript === 'strip'` 로 확인). 그래서 새 라이브러리·번들러 없이
`.ts` 를 그대로 import 해 실제로 호출한다 —
`docs/CLAUDE.md` 의 "새 라이브러리 설치는 승인 필요"를 지키면서 진짜 실행 검증을 얻는다.

`tests/export-list.test.mjs` **23검사**:

```
열 정의        헤더/추출기 결합 · 모든 행이 헤더와 같은 칸 수
이스케이프     쉼표 / 큰따옴표(2배) / 개행이 행을 쪼개지 않음 / 불필요한 따옴표 없음
의미 보존      가격 원본 · 병합 사건 미분할 · 유찰 0 은 0 · 없는 값은 빈 칸
빈 목록        0건이어도 헤더는 낸다(빈 파일은 "실패"와 구별되지 않는다)
TSV            탭 구분 · 쉼표를 감싸지 않음 · 값에 탭이 있으면 감쌈
★ 검사 도구 자체 검증   CSV 파서를 known-good 표본 6가지로 먼저 시험
```

마지막 항목이 중요하다 — **우리 코드가 만든 문자열을 우리 코드로 파싱하면 같은 실수를
두 번 해도 통과한다.** 그래서 검사용 파서를 표본으로 먼저 검증하고,
아래 5번에서는 아예 **바깥 소비자**로 읽었다.

## 5. 진짜 CSV 소비자로 읽어 확인했다

픽스처 API 의 실제 관심물건 응답으로 CSV 를 만들어 파일로 쓰고,
**파이썬 `csv` 모듈**(표준 라이브러리, 우리 코드가 아니다)로 읽었다.

```
[PASS] 엑셀용 UTF-8 BOM 이 붙어 있다
[PASS] 행을 실제로 읽었다(검사가 공허하지 않다)          6건
[PASS] 헤더가 기대한 열이다                              10열
[PASS] 모든 행의 칸 수가 헤더와 같다(열이 밀리지 않았다)
[PASS] 값 안에 쉼표가 든 행이 실제로 있다                 예: '상가,오피스텔,근린시설'
[PASS] 쉼표가 든 값이 한 칸으로 유지된다
[PASS] 감정가가 숫자 원본이다(축약 아님)
[PASS] 한글이 온전하다
```

★ 도중에 **"관심물건 0건"** 이 나와 헤맸다. 데이터가 없는 것이 아니라 **토큰이 401** 이었다 —
검증 스크립트가 자기만의 JWT 비밀값을 만들어서 서버(`.env` 값 사용)와 달라졌던 것이다.
*인증 실패가 "데이터 없음"으로 보이는 것*은 이 저장소가 반복해 경계해 온 혼동이라
스크립트에 그 이유를 주석으로 남겼다.

## 6. 실브라우저 확인

운영 DB 를 건드리지 않기 위해 **사본**에 관심물건을 넣고 그 사본을 읽는 API 로 확인했다.

```
클립보드 복사   7줄(헤더+6건), 모든 줄이 정확히 10칸
                가격이 2813645810 처럼 숫자 원본
                상태 알림 "6건을 복사했습니다 (표 프로그램에 붙여넣기)"
CSV 내려받기    파일명 관심물건_2026-08-20.csv / 1,505 B
                선행 바이트 0xEF 0xBB 0xBF
```

★ **측정 도구가 또 거짓말했다.** 처음에 `blob.text()` 로 읽고 `charCodeAt(0)` 을 봤더니
"BOM 없음"이 나왔다. `Blob.text()` 는 UTF-8 디코딩 과정에서 **선행 BOM 을 제거한다** —
문자열로는 BOM 유무를 알 수 없다. `arrayBuffer()` 로 바이트를 보니 **있었다.**
*이상한 값이 나오면 코드보다 측정 도구를 먼저 의심한다.*

## 7. 가드가 내 새 코드를 두 번 잡았다 (둘 다 옳았다)

### (1) 작은 글자를 늘리려 했다

```
[FAIL] text-xs 사용 횟수: 121 (상한 118)
```

버튼을 `text-xs`(12px) 로 만들었다. 상한을 올리는 것이 아니라 **`text-sm`(14px) 로
바꿨다** — 그 상한은 "작은 글자를 더 늘리지 말자"는 약속이고, 새 UI 를 만들며
상한을 올리는 것은 약속을 어기는 쪽이다. 접근성으로도 14px 가 낫다.

상태 메시지 색도 `text-gray-600`(7.56:1)을 골랐다 — 같은 자리에 흔한
`text-gray-400` 은 2.6:1 이라 AA 미달이다(Sprint 225 실측표를 그대로 썼다).

### (2) 상태 메시지를 두 노드로 나눴다

```
[FAIL] ★ 나타나도 읽히지 않는 상태 메시지: ExportButtons.tsx:92(message)
```

처음에는 `sr-only` 한 줄 + 보이는 한 줄(`aria-hidden`, 조건부)로 나눴다.
**한 줄로 합쳤다** — 항상 존재하는 `role="status"` 한 줄이 그대로 보이는 줄이다.
같은 말을 두 노드로 관리하면 한쪽만 바뀌는 어긋남이 생기고, 조건부 노드는 나타나는
순간을 놓칠 수 있다(Sprint 223 이 검색 결과 알림에서 택한 방식과 같다).

> 가드의 `sr-only` 예외 정규식이 속성 순서에 의존해서 내 코드를 건너뛰지 않았다.
> **순서를 바꿔 규칙을 피하지 않고** 구조를 고쳤다.

## 8. ★ 곁다리 발견 — 상한 계수기가 주석을 코드로 세고 있었다

(1)을 고치다 드러났다. `text-sm 을 쓴 이유` 를 **주석으로 설명했더니** 그 주석의
`text-xs` 가 사용 횟수로 잡혔다.

```
클래스            주석포함   코드만
text-xs              119      117   <- 주석 2개를 코드로 세고 있었다
text-gray-400        111      110   <- 주석 1개
```

이 파일은 `_strip_comments()` 를 **이미 갖고 있고** 형제 검사들은 쓰는데,
정작 상한 계수기만 원문을 그대로 셌다. 저장소 규칙
*"주석/문자열을 실제 코드로 세지 않는다"* 를 계수기만 어기고 있었다.

두 방향 모두 해롭다.

```
클래스를 **설명**하면 사용으로 잡힌다        -> 멀쩡한 코드가 빨간불
주석을 지우면 상한에 여유가 생긴다            -> 진짜 사용이 늘어도 통과
```

계수기가 주석을 빼도록 고치고 상한을 **코드 기준 실측값으로 재기준**했다
(`text-xs` 118 -> **117**. 래칫은 조일수록 낫다).

**변이 2/2 기대대로**: 주석에서 언급 -> 통과 / 진짜 코드로 사용 -> 실패.
